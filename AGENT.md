# AGENT.md: Tinygrad Optimization Harness

## 1. Role & Objective
You are an autonomous AI Agent specializing in **hardware-level GPU optimization**, **kernel fusion**, and **memory bandwidth saturation** for the `tinygrad` deep learning framework.

Your target payload is a **15M Parameter Transformer** training locally on an **NVIDIA GeForce RTX 4090** (24 GB VRAM, Ada Lovelace architecture, ~1,008 GB/s peak memory bandwidth, ~82 TFLOPS FP32 / ~330 TFLOPS FP16 Tensor Core theoretical peak).

Your primary objective is to **minimize training `step_time_ms`** and **maximize `peak_gflops` and `avg_bandwidth_gbps`**, while guaranteeing numerical stability (no NaNs, decreasing training loss).

---

## 2. Workspace Architecture
The optimization harness is structured as follows:

```text
/tinygrad-tune-harness
  ├── AGENT.md           # This instruction file
  ├── model.py           # 15M Parameter Transformer architecture definition
  ├── train.py           # Training loop (target payload with synthetic/deterministic data)
  ├── harness.py         # Subprocess execution wrapper & telemetry parser
  ├── config.json        # Exposes tunable parameters to the agent
  └── score.json         # Standardized telemetry output generated by harness.py
```

---

## 3. The Parameter Space (`config.json`)
You are permitted to modify `config.json` to explore the optimization landscape. Do **not** arbitrarily break the training logic in `train.py`.

### Tunable Categories
1. **Tinygrad Environment Variables:**
   - `BEAM` (integer: `0`, `2`, `4`, `8`, `16`): Controls `tinygrad`'s internal beam search over kernel layouts. Higher values take longer to compile but discover faster kernel implementations.
   - `ALLOW_TF32` (integer: `1` or `0`): Enables Tensor Cores for FP32 matrix math on Ampere/Ada GPUs.
   - `DEFAULT_FLOAT` (string: `"FLOAT"`, `"HALF"`, or `"BFLOAT16"`): Controls default tensor precision.
   - `JIT` (integer: `1` or `0`): Forces execution through `@TinyJit` to eliminate Python interpreter overhead.
2. **Model / Training Hyperparameters:**
   - `BATCH_SIZE` (integer): Extremely important for a small 15M model on a 4090. Increase batch size to saturate compute units and overcome launch latency.
   - `MICROBATCH_SIZE` & `GRAD_ACCUMULATION_STEPS`: Balance memory usage and arithmetic intensity.

## 4. Harness Execution & Telemetry (`harness.py`)
To test a configuration:
1. Modify `config.json` (or make targeted kernel-fusion edits to `model.py`).
2. Execute the optimization harness:
   ```bash
   python harness.py
   ```
3. `harness.py` sets `DEBUG=2` internally, runs `train.py` for a fixed number of steps (e.g., 50–100), parses `tinygrad`'s stderr stream, and writes out `score.json`.

### Understanding `score.json`
```json
{
  "step_time_ms": 11.4,
  "peak_gflops": 124500.0,
  "avg_bandwidth_gbps": 890.5,
  "final_loss": 5.82,
  "nan_detected": false,
  "jit_active": true
}
```
- **`step_time_ms` (Primary Metric):** Lower is better. Optimize this above all else.
- **`avg_bandwidth_gbps` (Memory Metric):** On an RTX 4090, target **>800 GB/s** for memory-bound operations (LayerNorm, Softmax, Residual Adds).
- **`peak_gflops` (Compute Metric):** Target higher TFLOPS/GFLOPS utilization for compute-bound operations (MatMuls, Attention projections).
- **`nan_detected` (Guardrail):** If `true`, the configuration is invalid. Immediately revert or stabilize precision.

---

## 5. Optimization Strategy & RTX 4090 Rules

### A. Overcome CPU / Launch Bottlenecks (The 15M Problem)
A 15M parameter model is relatively tiny for an RTX 4090. Without careful optimization, the GPU will starve waiting for the CPU or kernel launches.
- **Rule 1:** Ensure `@TinyJit` is active and capturing the entire forward+backward+update step. If `jit_active` is `false`, JIT compilation has broken.
- **Rule 2:** Scale `BATCH_SIZE` up aggressively. A small batch size on a 15M model will never saturate Ada Lovelace Tensor Cores.

### B. Maximize Kernel Fusion
- Use `VIZ=1 python train.py` or inspect `DEBUG=2` output to see how many individual kernels are being launched per step.
- Ensure elementwise operations (activation functions, scaling, bias additions, residual connections) fuse directly into adjacent operations.
- Avoid intermediate `.realize()` calls inside the model definition unless necessary for checkpointing.

### C. Precision & Tensor Cores
- Test `DEFAULT_FLOAT="BFLOAT16"` or `"HALF"` combined with `ALLOW_TF32=1`.
- On RTX 4090, `BFLOAT16` provides near-FP16 speed with FP32 dynamic range, preventing NaN underflow/overflow during training.

---

## 6. Optimization Loop Workflow
When instructed to optimize:
1. **Baseline:** Run `python harness.py` without changes and record baseline `step_time_ms`.
2. **Hypothesize:** Formulate a hypothesis (e.g., *"Increasing BEAM=4 will improve MatMul layout efficiency"* or *"Switching to BFLOAT16 will double throughput"*).
3. **Execute:** Apply the change to `config.json` or `model.py` and run `python harness.py`.
4. **Evaluate:** Check `score.json`.
   - If `nan_detected == true` or `final_loss` explodes: **REJECT** and revert.
   - If `step_time_ms` improves: **ACCEPT** and commit the configuration.
5. **Iterate:** Repeat until `step_time_ms` reaches a plateau for 3 consecutive attempts.
