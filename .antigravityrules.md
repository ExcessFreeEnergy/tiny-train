## 1. MINDSET: FORGET PYTORCH, THINK TINYGRAD
Tinygrad is NOT PyTorch. It relies on a much simpler hierarchy of abstractions: `Tensor` (user interface) -> `LazyBuffer` (virtual op scheduling) -> `UOp` (core IR/micro-ops).
- **NO `torch` imports.** Do not import PyTorch. Do not try to cast tinygrad tensors to PyTorch tensors.
- **NO `nn.Module` subclassing.** Models are just plain Python classes. You don't need `super().__init__()` unless you are subclassing a standard Python class.
- **NO `model.train()` or `model.eval()`.** Training states are managed contextually via `Context(TRAINING=1)`.
- **NO `forward()` requirement.** While you can use `forward()`, `__call__(self, x: Tensor) -> Tensor` is the canonical tinygrad standard.

## 2. STATE & PARAMETER MANAGEMENT
Because models are standard Python classes, `tinygrad` manages parameters dynamically by walking the class hierarchy.
- **Getting Parameters:** Use `tinygrad.nn.state.get_parameters(model)`. It will automatically find all Tensors requiring gradients.
- **Optimizers:** Initialize optimizers using the extracted parameters:
  ```python
  from tinygrad import nn

  opt = nn.optim.Adam(nn.state.get_parameters(model), lr=0.001)
  ```
- **Saving/Loading:** Use `tinygrad.nn.state.safe_save` and `safe_load`, along with `get_state_dict` and `load_state_dict`.

## 3. LAZY EVALUATION (Crucial!)
Tinygrad operations do not run immediately; they construct an execution graph. 
- You MUST explicitly evaluate a tensor to trigger the hardware kernel. 
- Use `tensor.realize()` to keep it on the device (GPU/accelerator) but force execution.
- Use `tensor.item()` (for scalars) or `tensor.numpy()` to execute the graph and bring the data back to the CPU.
- **Implicit Chaining:** In tinygrad, `.backward()` returns the `Tensor` itself (unlike PyTorch where it returns `None`). This allows chaining operations seamlessly, e.g., `loss = model(X).loss(Y).backward()`.

## 4. THE JIT (TinyJit)
To bypass Python and driver overhead, the core training step should always be wrapped in `@TinyJit`.
- `TinyJit` captures the computational graph. **No control flow (if/else) based on tensor values** is allowed inside a JITted function.
- All returned tensors inside a `@TinyJit` function MUST be explicitly `.realize()`'d.
- **Batch Sampling:** Always move batch sampling (e.g., `Tensor.randint`) INSIDE the JIT. Tinygrad will correctly re-roll the RNG on every step automatically, eliminating host-to-device slicing overhead.

## 5. CANONICAL TRAINING LOOP (The "beautiful_mnist" pattern)
This is the EXACT pattern you must use for writing training loops in tinygrad. It emphasizes graph fusion and JIT efficiency:

```python
from tinygrad import Tensor, nn, TinyJit, Context, GlobalCounters
from tinygrad.helpers import getenv


class Model:
    def __init__(self):
        # Plain python attributes. No nn.Module.
        self.l1 = nn.Linear(784, 128)
        self.l2 = nn.Linear(128, 10)

    def __call__(self, x: Tensor) -> Tensor:
        # Standard forward pass
        return x.flatten(1).sequential([self.l1, Tensor.relu, self.l2])


model = Model()
opt = nn.optim.Adam(nn.state.get_parameters(model))


# 1. Decorate the step with JIT and the TRAINING=1 Context
@TinyJit
@Context(TRAINING=1)
def train_step(X_train: Tensor, Y_train: Tensor) -> Tensor:
    opt.zero_grad()

    # 2. Sample INSIDE the JIT. Tinygrad handles RNG updates on every execution.
    samples = Tensor.randint(getenv("BS", 512), high=X_train.shape[0])

    # 3. Forward & Backward (chained because .backward() returns the tensor)
    loss = model(X_train[samples]).sparse_categorical_crossentropy(Y_train[samples]).backward()

    # 4. FUSE optimizer step and loss realization into a SINGLE execution graph!
    return loss.realize(*opt.schedule_step())


# 5. Outer execution loop
for i in range(10):
    # Reset counters so DEBUG=2 outputs are readable per-step
    GlobalCounters.reset()

    # Pass the ENTIRE dataset into the JIT. No .to(device) calls needed.
    loss = train_step(X_train, Y_train)

    # 6. Use .item() to pull the float out of the graph and print
    print(f"Step {i} | Loss: {loss.item():.4f}")
```

## 6. DATA & ACCELERATORS
- **Always use `uv`:** You must exclusively use `uv` for running Python scripts and managing dependencies (e.g., `uv run script.py`). Do not use standard `python`.
- **Hardware Agnostic:** You do not need to call `.to('cuda')`. `tinygrad` automatically assigns tensors to the default accelerator based on environment variables (e.g., `CUDA=1`, `METAL=1`, `CPU=1`).
- **Environment Toggles:** Use `tinygrad.helpers.getenv` for configuration variables (like batch sizes, steps, or toggles).
